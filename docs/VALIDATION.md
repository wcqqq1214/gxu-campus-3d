## 首版历史运行观测

1280 × 720 静态预览，基础场景像素比 1.75，相机移动样本约 **39 FPS**；较早图书馆近景样本约 **33 FPS**。流畅档将像素比降至 1.25，相机移动约 **27 FPS**（主动限制至约 30 FPS）。渲染按需进行，静止时不持续重绘；调试面板的 FPS 是最近一段活动帧采样，不是闲置帧率。

本地缓存命中时基础模型就绪约 **0.35 秒**，开发首载样本约 **3.70 秒**。它们不是互联网首访结果。`readyMs` 从浏览器页面时钟起算，在基础 GLB 就绪时记录，植物随后载入。

调试面板提供 `performance.memory.usedJSHeapSize`（浏览器支持时）、几何数量、纹理数量、三角形、Draw Calls、累计 GLB 字节及像素比。此次内置浏览器多轮测试的报告堆大小约 530—842 MiB；这是浏览器报告值，可能包含共享/回收尚未完成的开销，**不是独占物理内存或 GPU 显存测量**。正式站点首访的独立页面报告 JS 堆约 58 MiB，见下节；开发预览长时间反复热更新后的堆值不用于判断站点正常首访内存。

## 复现故障检查

```sh
npm run build:pages
npm run preview -- --fail-once=base.glb,east.glb
# 打开 http://127.0.0.1:4300/gxu-campus-3d/
# 基础模型首次失败，重试；选择图书馆，分区首次失败，再重试。
```

调试面板：在网页地址后增加 `?debug`。正式测试无需输入任何 API 密钥。

## 第二阶段 · 空间区块与加载

三个普通建筑分区改为 30 个 360 米空间区块，单块最大 1,675,948 bytes。通过并发队列、取消、临时错误重试与完整资产映射等 23 项检查。首屏模型及纹理共 5,920,672 bytes；基础文件保留 16 位几何位置、使用 7 位法线量化。

实际浏览器在本地故障服务器遇到 base.glb 和 library.glb 首次 503 后均自动恢复。图书馆近景驻留 1 个地标和 3 个区块，几何缓冲估算 43.6 MiB；返回全景后释放 3 个区块，只保留一处最近地标，降至 16.6 MiB。这个数值不是总内存或显存。Apple M5 / 16 GB / macOS 26.5.1、1280×720、像素比 1 的本地活动样本为 31—58 FPS；首次故障注入样本基础就绪 1,156 ms，另一次正常刷新为 2,498 ms。单次结果受本机负载和缓存影响，不等于互联网首访或手机真机表现。最终正常刷新加图书馆定位累计完成 9,959,112 bytes，恰等于基础资源与当前四份近景文件之和，无多余完成下载。
