# 入口、交通与景观保留区的最终排树

## 修复的问题

在[最终占地筛选](VEGETATION_FINAL_GROUND.md)之后，树干中心在范围外、树冠侵入保留区的晚加入树位仍可能被放行。早期生成已经有入口、桥梁通道、雕塑和运动场等树冠留白规则，本批将这些规则接到所有上游树位来源之后重新执行。

从当前场景选取11类人工测试点，分别位于公共道路、桥下通道、桥面、湖桥、入口、校门、雕塑、田径场、篮球场、看台及岸顶的保留范围边缘。旧最终步骤得到3,061株，11株全部放行；修复后得到原3,050株，全部测试点被排除，原树位属性与顺序保持。测试点仅在隔离副本使用。

## 最终执行顺序

1. 按最终派生占地范围筛选树干中心，保留内院孔洞。
2. 重跑本批32个模型树冠保留范围。
3. 执行汇学堂东草坪与图书馆北前场两处显式禁植区。
4. 构建模型时确定最终树根高程，再检查建筑表面及可识别闭合组件的包含。

| 保留范围 | 数量 | 采用规则 |
| --- | ---: | --- |
| 农院路 | 1 | 依据最终拟合路径、方向及可变路幅，保留既有1米范围余量 |
| 桥下通道、桥面 | 3 + 3 | 桥下范围含两侧抬高步道；桥面采用已有宽度参数 |
| 湖上桥梁 | 7 | 沿已生成桥梁路径按既有宽度设置 |
| 建筑入口 | 8 | 复用图书馆、六教、十教和国际学院公寓的已有入口保留范围 |
| 校门、雕塑 | 3 + 1 | 复用已标注校门边界；雕塑沿用精确圆心距离与半径 |
| 田径场、篮球场、看台 | 2 + 2 + 1 | 复用已生成运动范围与既有看台保留参数 |
| 已建岸顶 | 1 | 仅针对已建岸顶，不向整段湖岸泛化 |

树冠模型包络沿用 `4 × 树高 / 9 + 1 m`。这里表达显式模型禁植范围，不是现场树冠尺寸或三维碰撞判定。普通街道遮荫、未核对入口及没有资料的景观区域不新增整片树冠排除。

桥下最终范围使用实际展示的采样路径，与早期OSM未采样折线可能存在细小差异；两次约束共同生效，没有移除早期规则，也未将桥下空间压成单层地面。

## 实现与验证

[树冠保留规则](../scripts/vegetation_reservations.py)集中保存最终执行逻辑。[入口掩膜](../scripts/architecture_data.py)与[道路断面函数](../scripts/infrastructure_footprints.py)由早期准备和最终筛选共享。提取前后，4栋地标的8个入口范围，以及主路和3个桥面各两种余量的8组组合，坐标与拓扑完全一致。

70项Python数据测试通过，包含5项新增测试：精确雕塑距离边界、内院与局部留白、旋转入口、非对称变宽道路、11类当前场景晚加入树位及幂等处理。Pages构建通过，公共数据和69个模型与生产包逐项一致。

当前3,050株树、可编辑源文件与69个GLB逐字节保持。仅 `vegetation-zones.json` 新增 `finalCrownReservations` 并更新占地检查范围说明。首屏仍为5,897,824 bytes，最大普通近景区块1,684,868 bytes。本批不重新导出模型，也没有新的浏览器或FPS测量；已有模型净空说明依据相同树位与模型保留。

## 尚未完成

本批完成既有明确保留区的最终重查，不代表全校园道路、运动场、水边的实际三维净空验收。未校准的入口突出构件、普通道路合理遮荫及桥梁结构的实际模板碰撞仍需按几何与高度处理。直接改写公共树位文件后绕过数据准备，不在本次流程保证范围内。

后续已完成[当前场地实际网格检查](VEGETATION_SITE_CLEARANCE.md)：64个源场地网格、52个运行场地网格与两种运行树模板无表面或可识别闭合组件包含冲突。该证据对应当前资产哈希，不推定工程净空；新增树位和场地修改后需重跑。

有资料依据的行道树、庭院与低矮景观尚需落地；完整S2楼栋校准、S3邻楼联合验收及S5仍未完成。
