# 校园浏览体验优化

基于 2026-09-10 的桌面与手机尺寸浏览检查，按以下顺序改进。地图年代、模型证据限制和精选地标范围继续遵循 DATA.md、MODELING.md。

1. **面板与镜头**：统一手机底部面板；桌面可收起；镜头按建筑包围盒和面板占用空间构图。增加正面、背面、入口、俯视和环绕观察，图书馆提供南北入口。
2. **加载与内存**：将三个大分区拆成空间区块；优先加载当前地标；展示进度；限制并发和自动重试；卸载远处近景并恢复基础模型。
3. **精选导航与分享**：保留 14 处精选地标；支持类别、常用别名、位置小图、朝向及分享链接恢复视角和环境。
4. **视觉与易用性**：改善近景树冠、重复立面、入口铺装与阴影；统一夜景玻璃；加大触屏目标并改善小字对比度。

验证记录随阶段更新。浏览器调整窗口尺寸属于桌面模拟，不作为手机真机结果；GLB 下载体积不作为显存占用。

## 第一阶段 · 面板与地标视角

已完成统一面板、可收起菜单、包围盒自动构图、地标多视角、图书馆南北入口、环绕及手动暂停。夜景统一处理通用、图书馆和公寓玻璃，常用触屏按钮至少 44 像素。

通过 19 项自动检查（含 14 处地标、4 种视角、4 种屏幕布局的透视投影检查），并在浏览器 1280×720 与 390×844 尺寸检查图书馆全貌、北门及环绕暂停。手机结果为桌面浏览器模拟，未测手机真机。

## 第二阶段 · 空间区块与加载

三个普通建筑分区改为 30 个 360 米空间区块，单块最大 1,675,948 bytes。通过并发队列、取消、临时错误重试与完整资产映射等 23 项检查。首屏模型及纹理共 5,920,672 bytes；基础文件保留 16 位几何位置、使用 7 位法线量化。

实际浏览器在本地故障服务器遇到 base.glb 和 library.glb 首次 503 后均自动恢复。图书馆近景驻留 1 个地标和 3 个区块，几何缓冲估算 43.6 MiB；返回全景后释放 3 个区块，只保留一处最近地标，降至 16.6 MiB。这个数值不是总内存或显存。Apple M5 / 16 GB / macOS 26.5.1、1280×720、像素比 1 的本地活动样本为 31—58 FPS；首次故障注入样本基础就绪 1,156 ms，另一次正常刷新为 2,498 ms。单次结果受本机负载和缓存影响，不等于互联网首访或手机真机表现。最终正常刷新加图书馆定位累计完成 9,959,112 bytes，恰等于基础资源与当前四份近景文件之和，无多余完成下载。

## 第三阶段 · 精选导航、分享与近景（2026-09-10）

完成教学、生活、文体和校门分类，以及“六教”“二教”“大活”“新东园门”等常用别名搜索。索引继续限定为 14 处精选地标。位置小图采用实际建筑轮廓，显示选中地标、观察中心和镜头朝向；小图可收起，观察中心位于图外时明确提示。北向按钮同步显示当前方向。

分享链接记录地标、视角、镜头位置和光照。重新打开链接可恢复场景，并按可用画面调整到不同屏幕；对无效地标、非有限坐标和越界镜头进行过滤。本地实际复制“图书馆北门近景 + 夜景”链接，在 390×844 视口重新打开后，地标、入口和光照均恢复。浏览器同时验证“六教”“新东园门”搜索与四处校门筛选；导出按钮触发成功提示，控制台无错误。

普通建筑近景增加适度墙面与窗色差异、入口台面和铺装，未改变真实地理轮廓与高度规则。乔木近景采用平滑树冠，棕榈增加连续弧形叶轴和叶片；远景及流畅档继续使用轻量树木，精细档仅在镜头附近切换细节。夜景窗光、近景接触阴影和触屏按钮同步调整。这些立面和植物细节为示意补充，不能代替近期实拍资料。

最终通过 25 项 Node 检查、类型检查、Oxlint 与 Pages 生产构建。模型资源为：首屏 **5,920,728 bytes**，最大普通区块 **1,708,364 bytes**，按需近景植被模板 **41,304 bytes**，全部 GLB **31,234,824 bytes**，可编辑 Blender 源文件 **87,642,045 bytes**。首屏仍满足 6 MB / 12 MB 预算；此预算仅含模型与嵌入纹理，JS、JSON 与解码器另计。

同一 Apple M5 / 16 GB / macOS 26.5.1，1280×720、像素比 1，图书馆近景活动样本约 56 FPS、361 万渲染三角形、128 次绘制；不是持续压力测试或手机真机结果。手机尺寸检查及分享恢复截图见[移动端画面](screenshots/mobile-optimized.png)，最新网页全景见 [README 截图](screenshots/overview.png)。
