# 6B 小广场铺地校准

本工作包属于 [S4 普通场地推广](CAMPUS_REFINEMENT_PLAN.md)。对象为 `way/759147083`（6B 小广场），保留最终道路覆盖链中的五点轮廓，面积约 975.45 平方米。它验证普通铺地与主路的连接、露空边缘封口和内部穿地处理，不能代表全部校园铺地已校准。

## 资料与精度

- [OpenStreetMap 轮廓](https://www.openstreetmap.org/way/759147083)：名称与位置依据，采用当前固定快照及最终铺面覆盖结果，不根据照片重新扩大广场。
- [公共管理学院毕业季旧物接力活动](https://ggxy.gxu.edu.cn/info/1974/6949.htm)：2025-06-23 发布，报道活动发生于 2025-06-20 的西校园 6B 小广场。照片支持硬质铺地、红色分带、边缘坐台与树木的存在；首图可见 6B 楼号。
- 来源 ID `sixBMarket2025`，查阅日期 2026-09-13，单张照片拍摄日期未独立确认。加入公共来源目录后共 66 条；此前记录中的 65 条为各自历史快照。

照片未提供可测量的铺面高程、接缝坡度和花坛位置。本批没有重建红色分带、坐台和花坛，也没有把临时摊位加入常驻模型。邻楼形体与阳台仍属既有普通建筑表达，不能据这次铺地修改计作整栋校准。

## 修改前的实际问题

[原始边缘测量](model-checks/refinement/s4-paving-before-geometry.json)分别检查保存的 Blender 源文件和解码后的基础 GLB，每边取五个点：

- 西侧与主路连接处，最大高差约为源文件 21.5 厘米、GLB 21.3 厘米。
- 17 个露出边缘采样点没有侧面封口；铺面高于下面地形约 11–48 厘米。这来自显示偏移与不同采样方式，不是现实台阶测量。
- 增加内部网格采样后，还发现地形高于铺面最多约 15.5 厘米。画面中的绿色斑块与地形穿出相符。
- 原铺面大三角形的两侧细分不一致：一侧边中点重新采样 DEM，另一侧仍保留长边，导致同一边的高度不一致。已定位点约有 9.1 毫米差异；修复连续性会使局部内部铺面发生小幅变化，不能称为逐点完全不变。

无效的初次近景镜头及失败检查保留在本机工作目录和历史截图中。有效修改前画面采用 `s4-paving-before-visible` 的接缝/总览与 `s4-paving-before-edge` 的边缘镜头。

## 几何处理

人工输入为 [paving-overrides.json](../data/paving-overrides.json)，生成结果为 [pavings.json](../public/data/pavings.json)。配置绑定稳定铺面 ID、轮廓摘要、接缝边索引和来源，轮廓或最终上下文变化时拒绝使用过期结果。

1. 西侧接缝取最终主路实际三角面的高程，向广场内侧约 3 米过渡。约 2 米网格在过渡边界额外切分，避免插值越过调整范围。
2. 铺面按原有三角面细分，并统一共边顶点；保留原轮廓和其余形体，对原来的非连续边做局部连续性修正。
3. 只在原广场轮廓内压低穿出的地形，留出 0.12 米模型净距。地形与铺面的三角面相交后分别处理，保留轮廓外原地形平面；这是数值防穿插措施，不是对现实开挖深度的描述。
4. 露出边缘增加侧面，底部埋入原地形约 0.06 米。已有道路开口保持开放，不把整个广场围成路缘墙。
5. 与主路接触的窄带移到独立精度节点，沿用原道路三角面。接触深度 1 米、两端余量 0.5 米、埋藏重叠 0.15 米均为防止量化接缝的建模参数。

节点 `paving-six-b-plaza` 和 `paving-six-b-plaza-contact-0` 常驻基础模型，均属于 `roads` 图层。源对象保留铺面和侧面顶点组。未增加精选地标或改动建筑轮廓。

## 复现与验收范围

完整数据准备在入口场地之后运行 `scripts/paving_data.py`，再准备岸段与植被。单独更新相关道路或场地后，应刷新铺地与岸段派生数据，再构建模型。模型构建仍是树根高程的最终写入步骤。

```sh
python scripts/paving_data.py
python scripts/shore_data.py
blender --background --python-exit-code 1 --python blender/build_campus.py
blender --background --python-exit-code 1 --python blender/validate_paving.py
```

Python 命令需使用仓库约束环境。专项验证同时读取本机保留的修改前资产 `work/refinement-s4-shore-complete/`；该副本不是公共分发依赖。复现前后对照时须恢复对应版本，不能拿当前模型充当修改前基线。

验证覆盖原有 25 个边缘点、101 个密集接缝点、原始道路接触面、全部露出边缘、内部网格和轮廓外道路/地形。源几何误差与全校园 Draco 量化误差分开记录；原不连续三角边的内部修正单列容差与实测值。

## 2026-09-13 接续：纹理条带修复与增量维护

条带来自导出精度与细分三角面的组合。原地形位置采用 15 位量化，纹理坐标使用导出器默认的 12 位量化；覆盖整个校园的量化范围使新增小三角面产生位置重叠及纹理偏移。独立改变位置/纹理精度的实验确认：只提高纹理精度能消除大部分条带，但仍保留位置量化造成的细线。

`blender/terrain_export.py` 对地形节点采用匹配的 18 位位置与纹理精度，再将该节点的压缩数据放回基础 GLB，并清除已经不用的二进制数据。其他节点维持原有导出精度，不增加运行时模型或 Draw Calls。首屏模型及树模板共 **5,892,096 bytes**，仍满足 6,000,000 bytes 门槛。

另有一个极小三角面因浮点法线不稳定，误用了侧向纹理投影。投影修正仅作用于广场边界框及 1 米边缘范围，其他地形与下穿区域的原投影保留。[源文件对照](model-checks/refinement/s4-paving-precision-source.json)确认全部地形顶点和面索引不变，只有该三角面的 3 个 UV 角点改变，范围外 UV 不变。

[实际纹理与覆盖检查](model-checks/refinement/s4-paving-terrain-texture.json)覆盖 1,000 平方米区域：源文件、GLB 各 100,000 条射线均未发现缺口，所有检查点的 UV 均符合地面 `XY/4` 投影。该区域压缩三角面的投影重叠由约 1.91 平方米降至约 0.025 平方米；压缩仍存在有限误差，不能称为测量精度。当前 GLB 的铺面最小净距为 114.24 mm，密集接口最大高差仍为 1.11 mm。

[最终图层画面](model-checks/refinement/s4-paving-precision-final-layers-interaction.json)的七种状态已逐张核对：道路关闭时地形条带消除；铺面、建筑与植被的关闭/恢复和夜景显示正常，页面及资源错误为零。固定镜头的前后图在历史记录中保留。

[两份隔离副本](model-checks/refinement/s4-paving-incremental-summary.json)分别把 `joinFeather` 从 3 米改为 4 米，再实际运行 `update_roads.py` 和 `update_basketball.py`。两者均更新源文件与 GLB 的铺地、地形，保留其他 81 个基础节点。独立计算的 4 米过渡检验点与 GLB 相差约 0.15 mm，同时与旧 3 米响应相差约 29.4 mm，证明参数已实际生效。铺地、纹理、图书馆场地及全部树根检查通过；测试参数未写回生产。

当前通过 52 项 Python 数据/导出测试、4 个针对性几何场景、54 项网页/资产测试及静态构建。[11 张人工核对画面](model-checks/refinement/s4-paving-precision-visual-review.json)与[当前几何快照](model-checks/refinement/s4-paving-precision-geometry.json)已绑定到同一模型版本；生产包和 69 个模型哈希重新核对一致。

性能测量在建模与专项检查结束后独立进行。首轮精细 60/60/60、流畅 30/30/30 FPS，三次结果的中位数分别为 60/30；渲染三角形相对 S0 增加 2.62%/4.53%，Draw Calls 增加 1.12%/1.49%。但外部 Python 在约 70 秒采样跨度内累计增加约 69 秒 CPU 时间，期间还有 Blender 活动，不能判定同条件通过。

接续复测为精细 60/60/60、流畅 28/27/27 FPS；流畅中位数比 S0 下降 10%，恰在门槛上。两档三角形增加 2.62%/4.82%，Draw Calls 增加 1.30%/5.22%。本轮又记录到一次外部 Python 97.6% CPU 活动，运行约 2 秒、累计 CPU 3.71 秒；采样不足以确定完整持续时间，不能把它归为持续满载，也不能排除干扰。见[复测报告](model-checks/refinement/s4-paving-precision-recheck-browser.json)及[进程条件](model-checks/refinement/s4-paving-precision-recheck-performance-context.json)。
