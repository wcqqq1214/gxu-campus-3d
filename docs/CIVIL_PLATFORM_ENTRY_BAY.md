# 结构平台：柱廊入口宽跨

2026-09-30，接续[OSM入口与柱列冲突](CIVIL_PLATFORM_ENTRY_EVIDENCE.md)。本批修正 `way/957404988` 东侧柱廊的等距六柱估算，使较宽开间对应入口一带；门洞、台阶及道路连接尚未实现。

## 依据与估算

重新直接核看[GX720全景658](https://www.gx720.net/pano/viewer/?slug=pano-658)原瓦片 `4/b/6/7.jpg` 的柱廊局部：连接北楼一侧的玻璃门区有较宽柱间，向低窗翼一侧的柱间较密。局部放大只便于观察，没有增加原图分辨率。全景配置的最大立方面为4096像素、对应现有第4级，未使用生成式补图或声称取得更清晰的现场照片。

[OSM入口节点7096023516](https://www.openstreetmap.org/node/7096023516)给出东侧柱廊上的地图位置。该点向后墙投影时，原等距布置的第三根柱阻挡中央路径；这与照片中的宽跨关系不符。六柱数量、米制尺度及节点精度仍未独立测绘，不能据此声称已恢复真实结构轴网。

采用保留首末柱的有界估算：原31.073米柱廊前缘两端各退2米，剩余27.073米分成六个基本开间；在距北端第三个网格位置不布柱，形成北侧两柱、南侧四柱的六柱组合。基本柱距约4.512米，宽跨约9.024米，其余四跨约4.512米。圆柱直径0.65米、顶板、0.24米地坪、3.6米退后墙线和分格玻璃均沿用原值。

这里的宽跨是柱间轴线距离，**不是门宽**。没有将2.2米诊断探测门宽写入生产配置，也没有据柱间宽度增造大门或整段台阶。真实门框尺寸、柱基形制、台阶级数和进深仍须校准。

## 验证范围

在原平台检查参数后增加 `--entry-bay`，保留历史等距六柱的旧检查路径。新检查覆盖六个柱位、五个开放柱间和地坪，并从固定OSM投影位置及左右0.6米处，在三个高度检查无遮挡直达后墙。该项证明当前模型中央通路净空，不代表门、台阶或完整通行路径验收。

源模型、基础模型及近景模型各511项检查通过；旧等距模型在新增检查中失败，反例有效。OSM中央投影路线到最近柱边约2.204米。247项Python、62项Node、类型检查、lint、完整模型及Pages构建通过，普通建筑、道路和树冠回归通过。

仅调整四根中间柱的位置，首末柱不变；其他447栋记录、六分部轮廓、玻璃、屋顶及既有入口保持。532个其他非树源对象、3,063株树、1,085个GeoJSON几何及67个非目标GLB保持。首屏模型5,399,896字节，比前批增加16字节；最大普通近景1,684,868字节。

11张固定对照、树木开启、夜景及手机视口画面已直接核看。靠北楼的宽跨在正面近景可见，其他视角保持原主体和屋面；远景及手机尺寸不足以确认真实柱网尺度。[修改后正面](screenshots/refinement/s2-platform-entry-bay-final/after/entry-bay-east-trees-off-day.png)。

同条件精细档60/60/60 FPS、流畅档30/30/30 FPS；相对同系统S0，三角形增加4.45%/10.70%，绘制调用增加2.93%/11.79%，符合原预算。三次LOD往返无错误，六张回归画面已逐张核看；27次CPU快照在六个计时窗口未记录到达到2%阈值的Python/Blender活动，十秒采样不代表设备完全隔离。69个模型与生产包匹配。[本批汇总及资产指纹](model-checks/refinement/s2-platform-entry-bay-summary.json)通过柱列局部联合验收，不增加整栋完成数。

[原始冲突记录](model-checks/refinement/s2-platform-entry-bay-prior-candidates.json)独立保留；最新[入口诊断](model-checks/refinement/s2-platform-entry-candidates.json)继续保持 `productionReady: false`，即使中央探测路线通过，也不将其升级为已完成入口。
