# 植被与闭合建筑组件的包含检查

本批补充最终排树规则中的一种漏检：树木完全位于封闭建筑内，或建筑组件完全位于封闭树冠内时，双方表面可以没有任何相交三角形。旧BVH表面检查会保留这种情况，新规则在表面检查之后继续检查双向包含。

## 实现与适用范围

`blender/mesh_volumes.py`按共享边划分三角网组件，合并重合面顶点、去除退化及重复三角形，重建一致的面朝向。只有每条边恰有两面且可一致定向的组件才用于体积判断；开放或非流形组件不自动封口。

包含判断采用闭合面的立体角总和。表面不相交时，对每个相连组件取代表点，分别检查树组件位于建筑闭合体内、建筑组件位于树冠闭合体内两种情况。原有AABB与BVH表面检查保留，基础和近景都参与。

检测时的重合顶点使用微米坐标网格归并，仅处理计算拓扑，不修改导出几何。16米空间索引用于检索附近的闭合组件与代表点，避免每株树遍历整个导出区块内的大量窗框；它不改变树位间距或碰撞判据。

## 回归场景

旧规则在“树冠完全位于闭合房间内”场景失败，新增规则通过。现有5类表面、LOD及稳定性检查与10类包含场景全部通过。另用两组索引等价检查覆盖负坐标、格子边界和超大闭合壳体，与逐组件扫描的结果一致。

| 场景 | 结果 |
| --- | --- |
| 树冠完全位于建筑内、建筑完全位于树冠内 | 排除，记录包含方向与见证点 |
| 有内院孔洞的闭合环形建筑 | 内院中的树保留 |
| 缺底面的开放壳体 | 不自动封底，记录未覆盖组件 |
| 由独立柱和屋面组成的架空通道 | 通道内的树保留 |
| 面朝向混乱、重复面 | 仍识别闭合体 |
| 多块互不相连的树冠 | 分别检查，包含后续组件也能检出 |
| 不同位置、地面高程、旋转与缩放 | 双向包含均正确 |

测试命令：

```sh
blender --background --python-exit-code 1 --python blender/test_tree_clearance.py
blender --background --python-exit-code 1 --python blender/validate_tree_clearance.py -- --report-prefix=s4-solid-check
```

第二条从保存源文件及实际解码GLB读取几何。包含算法与生成器共用，资产收集和实例变换单独执行；固定几何回归场景用于验证算法本身。因此不将该检查描述成两套完全独立的包含算法。

## 尚未覆盖的空间

开放、非流形及导出接缝不闭合的组件不参与实体包含判断，仍执行表面相交检查，并在报告中单独计数。计数对象包括窗框等构件，不能当作完整建筑数量。

部分普通建筑主壳底面开放，因此本规则不能单独证明所有建筑内部都无树。完整验证还需要前置建筑平面排除、最终道路/水体/运动场/入口排除与有依据的禁植区规则共同覆盖。本批不将这些尚未完成的S4事项标为已通过。

## 当前场景集成结果

完整重建得到3,050 → 3,050株，17组回归全部通过。保存源文件的452个建筑网格及实际解码的95个基础/近景网格均未发现表面或已识别闭合组件的包含冲突。检查发生在重建前；重建后源对象几何、UV、材质与变换一致，69个GLB及全部树行逐字节一致，作为报告沿用到当前资产的依据。

Pages构建通过，生产包与公共资产一致；首屏模型5,897,824 bytes，最大普通区块1,684,868 bytes。公共数据仅更新排树方法说明。渲染资产与前端未变，因此没有重跑浏览器和性能，也不声称取得新的FPS结果。开放组件及完整场地排除仍需继续补齐。
