### S1 实现内容

`scripts/building_forms.py` 在数据侧解析普通建筑形体，`blender/generic_buildings.py` 负责共享主体、屋顶和入口，再附加远近立面。独立地标、荟萃楼、主席台及纪念柱继续使用专用模型。

- 430 栋普通建筑（含紧邻校界建筑）采用同一套基础/近景形体；可编辑源文件区分主体、屋顶、入口平台及窗格四组。
- 移除仅近景生效的轴对齐坡顶规则。原规则涉及 12 栋校内普通楼，未获屋顶资料者使用标注为估算的平顶。
- 第五教学楼和广西房地产及住宅研究会沿用 OSM `roof:shape=hipped`。矩形屋顶跟随实际楼栋方向；第五教学楼的复杂坡顶约束于原轮廓。2.3 米屋脊抬升和坡度仍是展示估算。
- 食堂形制与生活用途分类分离，7 栋餐厅不再按宿舍规则附加阳台。宿舍/住宅阳台仍为类型推定，尚未逐栋核对。
- 窗层数使用数据中的层数，避免将 30 米、7 层的机械工程学院重新排成 9 层窗。基础和近景共用有限的墙面材质与女儿墙轮廓。近景玻璃仍保留按稳定 ID 生成的确定性色差。
- 默认最长边入口仍明确标为示意，但门、雨棚与平台已共用于两个细节级别；真实入口定位将在 S2 校准。

### 可重复性处理

探索完整数据重建时发现，新旧 Shapely 版本会对 8 个既有轮廓产生不同简化结果。新增 [constraints-geodata.txt](../scripts/constraints-geodata.txt)，固定为原处理链使用的 Shapely 2.0.7、NumPy 2.0.2、Pillow 11.3.0、mapbox-earcut 2.1.0，并在 Python 3.12 环境中使用。

完整准备链还会重新推导前期增量更新过的校外围道路与一个主路边缘分区。S1 使用 `building_forms.py` 的普通建筑增量入口，只更新当前标准化快照中的形体字段，再完整重建所有模型；没有将这类场地变化混入屋顶修复。[数据不变项报告](model-checks/refinement/s1-data-invariants.json)确认原建筑字段、轮廓以及其他场地/植被数据保留。完整 `prepare_geodata.py` 也已接入同一形体解析函数。

建议环境与命令：

```sh
python3.12 -m venv work/refinement-venv
work/refinement-venv/bin/pip install -r scripts/requirements.txt -c scripts/constraints-geodata.txt
work/refinement-venv/bin/python scripts/building_forms.py
npm run models:build
work/refinement-venv/bin/python -m unittest discover -s scripts -p 'test_*.py'
blender --background --python-exit-code 1 --python blender/validate_generic.py
```

运行 npm 检查和生产构建时使用 Node.js 24。浏览器验收脚本为 `scripts/check-refinement-browser.mjs`，读取 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`；默认预览地址为端口 4300，输出位置按阶段区分，并拒绝覆盖已完成记录。

### 性能调整记录

首个共享形体版本将每栋楼的暖冷墙面材质同时带入基础层；图书馆环绕前两次采样的绘制调用中位数达到 624，相比原基线约 537 超出 15% 门槛，帧率也下降。因此改为共用既有用途墙面材质，保留所有主体、屋顶和入口几何；墙面色差细化推迟到后续阶段。原始未通过样本保存在 `s1-browser.json`，修正版本另行记录。

第二轮 `s1-validated-browser.json` 的六次环绕及三次近景/全景切换均执行完成，无浏览器错误。精细档绘制调用增加 9.12%，但流畅档增加 15.30%，仍超过 15% 门槛，未将其作为通过结果。随后将示意入口的玻璃与平台复用普通楼窗玻璃、石材，减少每个区块的独立材质，不改变入口几何。
