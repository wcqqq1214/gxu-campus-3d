OSM 上层要素带 `bridge=yes`、`layer=1`，名称是农院路，**没有直接提供 `bridge:name`**；桥名是结合校方资料和路网匹配的结果，保留在独立地标中。查询所含七座跨水桥的位置与跨水关系来自 OSM，桥名未知时只记录要素 ID，不编造名称，也不加入导航。

原始 OSM 道路中心线保存在 GeoJSON。显示模型对尖角进行平滑过渡，避免宽路面在弯道内侧翻折；本快照最大中心线调整约 3.15 米，属于估算路幅内的展示处理。各分段共用接缝切向，桥段与端点保持对齐。

桥面与引道共用连续沥青面层。找平区间由 OSM 桥段的两个端点确定，端点替换附近的常规采样点，避免过密采样使路缘翻折，也避免斜交处偏心的交叉点让桥端提前下坡。桥台止于梁板底部，取消未获照片依据的横向接缝叠片，避免混凝土顶面与路面重叠形成斑驳拼接带。

原 OSM 校园轮廓仍作为来源要素保存。另生成 `nongyuan-public-corridor` 与 `campus-display-area`：前者表示估算道路带，后者从校园展示范围扣除该道路带。公共道路属性来自用户现场指正；校方资料辅助核对围墙及立交关系。这不是地籍确权图，也不表达现实入校权限。小图用棕线显示公共农院路。

## 模型内容与估算范围

- **农院路**：连续车行道、分段沥青纹理、双向箭头和中心线、路缘石、红色步道、盲道、灯杆、带柱帽的围栏及三角梅示意。已映射的平交入口处断开围栏，立交处保留上下分层。
- **三处立交**：梁板、桥台、上层防护栏、下穿坡道、挡墙、排水盖板、金属护栏。车道两侧另建抬高的独立步道，护栏沿步道高程穿过桥洞，外侧挡墙衔接地面。崇左桥另有中央桥墩、大小圆形栏板和竖向题名。两侧题名布置属于历史照片启发的估算。
- **七座湖上桥梁**：按 OSM 路径生成桥面、护栏、桥墩及两端高程衔接；外观为通用估算，未宣称逐桥实景复原。
- **地形与景观**：精确裁剪 58 个粗 DEM 单元及相交铺地，开口包含车道、两侧步道和桥面下方，防止草地填住通道；累计移除 46 株与道路、桥洞及步道相交的示意树。

当前农院路常规段按车行道宽 10 米、两侧步道各 2 米建模；临街建筑密集处只收窄靠建筑的一侧并渐变衔接，模型中最窄车行道约 5.11 米、最窄步道 1 米。最低梁底建模净空约 4.5 米。这些是视觉建模参数，**不是实测尺寸、交通限高或工程建议**。实际路幅分布、坡度、围墙连续性、灯具数量、未见的桥台形制与桥墩分配均有估算。荟贤桥路段照片提供的材质延伸到公共农院路，仅是示意配置。

桥下独立步道与上述农院路路侧步道分开建模：桥下每侧按 2.2 米宽、梁底至步道面最低约 2.45 米净空估算，步道通过缓坡接回校园地面。崇左桥的抬高步道关系依据用户现场指正，2023 年照片辅助核对护栏与内侧挡墙；其余两桥的完整步道形制尚缺近期照片，保留通用估算说明。荟贤桥斜交处的桥台按整个行人通道避让，避免原矩形桥台封住一侧步道。

## 临街建筑避让

原固定路幅与 9 栋建筑的 OSM 轮廓重叠；实际网格检查还发现体育馆附楼填入轮廓凹口。此次保留全部建筑位置和原始轮廓：路面根据建筑外轮廓预留 2.2 米用于入口、阳台等生成细部，实际四边形路面与轮廓的最小平面间距约 2.192 米。宽度变化提前以每米不超过 0.12 米的速率渐变，所有分区共用断面，车道线、盲道、路缘、灯杆与围栏同步跟随。围栏在缺少建筑余量的路段留空。

荟贤桥临近东校园西区 8 栋的一侧，梁板、护栏和桥台按相同断面调整；桥底步道仍连续贯通。体育馆按现有 OSM 凹形轮廓恢复南侧主体和较窄北翼，不再用整块外接矩形填满临路空地。上述调整属于几何一致性修复，宽度、渐变、留距和未见立面仍为展示估算，没有新增测绘或照片证据。

## 运行与重建

[预处理脚本](../scripts/infrastructure_data.py)读取已提交的补充快照，生成 `infrastructure.json`、轻量小图、GeoJSON 派生范围及桥梁精选目录。完整 `prepare_geodata.py` 会自动调用它。

```sh
npm run data:restore
work/venv/bin/python scripts/prepare_geodata.py
npm run models:build
blender --background --python-exit-code 1 --python blender/validate_infrastructure.py
blender --background --python-exit-code 1 --python blender/validate_road_buildings.py
npm run typecheck
npm test
npm run build:pages
```

只改道路推导参数时可直接运行 `work/venv/bin/python scripts/infrastructure_data.py`，随后完整构建模型。更新地图时需分别刷新校园主快照和 `data/snapshots/infrastructure.overpassql` 对应的道路补充快照，更新脚本路径及来源日期；不能只刷新建筑数据却宣称桥梁同步更新。

Blender 源文件使用米制坐标，保留具名对象、材质和构件分组。基础场景包含完整道路位置、桥梁体量、坡道和地形开口；近景增加 9 个道路区块、7 个跨水桥区块和 3 个独立精选桥梁。它们随 GitHub Pages 托管，无地图密钥或后端依赖；远处沿用基础 LOD，近景按需加载。

网页增加“路桥”筛选、农院路搜索别名和“桥下近景”。桥下机位沿实际下穿坡道定位，适配竖屏时避开挡墙遮挡。桥梁模型、标注、拾取随“道路与桥梁”图层统一开关；普通建筑与无可靠名称的湖上桥不进入精选导航。

## 验证记录

几何检查直接读取可编辑源文件和实际发布的 Draco GLB，检查两侧车道的地面、梁底净空、双向通道贯通，并检查道路标线法线与源文件构件分组。新增检查覆盖两侧步道的完整长度和三个横向位置：地面连续、站立净空、双向通行以及护栏与桥体的实际面相交；基础 LOD 与精细 GLB 分别回读；另用桥上路面射线检查挡墙顶盖是否穿出。数据检查覆盖公共道路属性、保留原校界、三处短坡道与校道衔接、车道及步道地形开口和资产清单。输出：[infrastructure-geometry-check.json](model-checks/infrastructure-geometry-check.json)。
