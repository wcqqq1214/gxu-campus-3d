# 广西大学三维校园优化计划（基于 6pro 建议）

> 整理日期：2026-09-12；本次更新：2026-09-13  
> 依据：用户提供的 6pro 项目优化建议，并结合当前仓库结构整理。  
> 文档性质：规划稿。下面的任务和验收条件不代表已经实施或通过验证。已有执行情况见 [实施计划](CAMPUS_REFINEMENT_PLAN.md)与[执行记录](CAMPUS_REFINEMENT_PROGRESS.md)。

6pro 原建议属于源码与数据层面的诊断，其中的视觉问题包含尚需画面对照的推断。本计划据此安排核验与实施；阶段清单中的复选框表示规划要求，实际完成状态统一由执行记录管理。

本轮目标是提高校园的地点辨识度和空间可信度。优先让建筑拥有合理的高度、屋顶和入口，让道路、前场、台阶及绿化形成连续空间，再增加局部表现细节。

首轮集中交付三项成果：**普通建筑远近景形体一致、20–30 栋重点普通建筑的逐栋校准、图书馆北入口及周边的完整场地样板。**

| 首轮成果 | 要解决的问题 | 可交付的验收证据 |
| --- | --- | --- |
| 远近景形体一致 | 切换细节级别时屋顶或主体发生变化 | 同一楼栋两级模型的形体检查与切换对照 |
| 20–30 栋重点建筑校准 | 默认高度、用途模板与示意入口不足以表达楼栋身份 | 逐栋来源、参数变更、未确认字段及验收记录 |
| 图书馆北入口场地样板 | 建筑、台阶、前场、道路和绿化缺少联合核验 | 固定镜头对照、连接几何检查与同条件性能报告 |

本次交付为计划文档。实施时以阶段验收推进，已有成果先核对再复用；本文不把原建议中的代码推断视作已复现缺陷，也不把历史统计视作当前实测。

### 如何使用这份计划

- **确定投入顺序：** 先看第 2 节阶段安排；前三项成果优先于材质和装饰细化。
- **领取具体任务：** 按第 11 节工作包和第 12 节首批步骤推进，每批明确楼栋 ID 或场地边界。
- **判断是否完成：** 使用第 9 节统一验收标准和第 10 节记录模板，将局部改进与整栋、整片场地验收分开统计。
- **接续已有工作：** 查阅[实施计划](CAMPUS_REFINEMENT_PLAN.md)和[执行记录](CAMPUS_REFINEMENT_PROGRESS.md)，复用已有实现；本规划稿的复选框不充当实时进度表。

本次仅整理计划、核对仓库文档与实施入口，没有重新构建模型或运行浏览器验证。原建议提到的数量、性能及视觉问题需按 S0 重新核验后用于实施决策。

## 1. 范围与基本原则

6pro 建议记录了 448 栋建筑（校内 435 栋、紧邻校界 13 栋）、20 处精选地标，以及 347 栋按类型估算高度的建筑。这些数字属于建议所依据的诊断快照；实施前应重新统计，不直接作为当前完成率的分母。

沿用现有米制坐标、OSM 建筑轮廓和内院、空间分块、独立地标加载、植被实例化及性能预算。保留已经建立的运动场平整、主路铺装、农院路上下分层、桥洞裁剪和下穿接口。

本轮遵循以下原则：

- 建筑主要形体由资料及明确的默认规则决定，细节级别只控制小构件的表达。
- 导航用途与建筑形制分开；食堂属于生活设施，不意味着应该具有宿舍阳台。
- 校准以稳定建筑 ID 为单位，原型用于解释已有轮廓之上的形体。
- 层数、层高、主体高度、屋顶高度分别记录依据；确认层数不等于测得高度。
- 场地高差使用局部几何表达；DEM 提供背景地势，显示偏移不能当作实际结构高差。
- 绿化先明确树位、组织与留白，缺少资料的区域保持示意标注。
- 每批同时交付数据、模型与验证证据，优先投入能改变轮廓和空间关系的几何。

### 本轮暂不安排

- 更换渲染引擎、重写整套建模流水线或扩大校园覆盖范围。
- 全校 DEM 无差别加密、全校压平，或用随机高度制造楼群差异。
- 批量替换高面数树木、在缺乏资料的空地补花坛和特色树种。
- 在高度、屋顶、入口与场地连接尚未核对前，全面增加窗框、屋瓦和装饰。

上述工作只有在试点暴露具体限制、且现有方法无法解决时才重新评估。它们不作为首轮三项成果的前置条件。

## 2. 阶段安排与依赖

| 阶段 | 优先级 | 主要任务 | 阶段交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- | --- |
| S0 | 前置 | 建立基线、样板范围和候选楼栋清单 | 数据统计、固定镜头、性能基线、候选表 | 修改前状态可复现，候选均有稳定 ID |
| S1 | P0 | 统一基础与近景建筑形体 | 共享形体规则、屋顶一致性检查 | 屋顶、主体、内院及主要入口不随 LOD 改变 |
| S2 | P1 | 建立校准数据，先试点后扩展 | 5–8 栋试点，随后扩展至 20–30 栋 | 来源可追溯，校准数量与待核对数量分开 |
| S3 | P1 | 完成图书馆北入口场地样板 | 连续入口空间、绿化留白、邻楼校准、对照图 | 几何、画面、加载和性能联合通过 |
| S4 | P2 | 推广植被分区与局部场地处理 | 有依据的植被分区、代表性湖岸和铺地边缘 | 规则可复用，既有空间约束无回退 |
| S5 | P3 | 局部材质、小构件细化及总体验收 | 有可见收益的细化、完整交付包 | 首轮与推广范围全部达到验收要求 |

执行顺序：**S0 → S1 → S2 试点 → S3 → S2 扩展与 S4 → S5。** 资料整理可以提前进行，共享数据流程和生成资产按批次集成。已有实现先复核，符合要求的部分直接复用。

首轮完成指 S0、S1、S2 的 20–30 栋及 S3 全部达标；S4、S5 为后续推广。排期在 S0 清单和首批试点成本明确后制定，不预先承诺缺少资料支撑的日期。

### 从当前仓库接续

启动实施时先检查已有基线、共享形体模块、人工校准表和场地模块。复核通过的成果直接沿用；未覆盖的字段、区域与验收项继续进入对应阶段。每项任务至少记录“待取证 / 部分实现 / 待验收 / 已验收”状态和证据位置，避免把存在配置文件或生成模型视为完成。

### 实施前的问题核验表

以下是原建议提出的问题及核验方法，不代表这些问题在当前版本中仍然存在。核验结果应记录为“仍存在 / 已修复并验证 / 尚不能确认”，再决定具体修改范围。

| 原建议中的问题或判断 | 实施前如何确认 | 核验后采取的动作 |
| --- | --- | --- |
| 347 栋建筑按用途估算高度 | 重新统计当前生成数据中的高度依据，并抽查人工覆盖结果 | 以当前清单选择 S2 候选，保留原统计作为历史快照 |
| 生活类建筑可能统一生成阳台 | 对照食堂、宿舍的分类、形制配置及实际导出模型 | 只修复仍由用途错误推导的形制，已有正确覆盖继续保留 |
| 部分普通楼基础为平顶、近景为坡顶 | 检查共享形体代码，并比较同一稳定 ID 的两级实际模型 | 若问题仍在，优先修复；若已解决，留下回归证据 |
| 最长边中点可能不是真实入口 | 将回退入口与可定位照片、地图方位逐栋对照 | 有证据时覆盖入口；无证据时明确保留为示意 |
| 通用铺地的显示偏移可能造成悬边 | 检查实际地形、铺面断面和低视角画面 | 按具体接口补侧面或过渡，不批量将显示偏移解释成台阶 |
| 散点树位可能影响前场、草坪和入口 | 在固定镜头中检查空间用途，并核对树冠与通行范围 | 优先调整有依据的树位及留白，再评估模型细节 |
| 新增几何可能增加渲染负担 | 在当前资产、相同设备与镜头下建立性能基线 | 按本计划的回归门槛逐批验收，不沿用历史面数作实测结论 |

## 4. S1：统一远近景形体

主要入口：`scripts/building_forms.py`、`blender/generic_buildings.py` 与 `blender/build_campus.py`。当前仓库已有共享形体模块，应先核对它对原建议中问题的覆盖程度。

- [ ] 统一解析主体高度、屋顶、局部方向、内院、附楼及主要入口参数。
- [ ] 基础与近景使用同一套主要形体；近景只增加窗框、细栏杆等小构件。
- [ ] 移除屋顶类型对世界坐标轴方向、矩形条件及近景分支的依赖。
- [ ] 没有依据的屋顶使用明确标注的保守默认值；有依据的坡顶沿楼栋局部方向生成。
- [ ] 窗层数使用最终采用的建筑层数，避免生成器重新按默认层高覆盖校准结果。
- [ ] 同步可编辑源文件、基础模型、受影响近景区块与资源清单。

**验收：**覆盖旋转矩形、内院、凹形、附楼及原屋顶规则命中的实际样本。源文件和实际 GLB 的屋顶、主体高度、内院、主要入口保持一致；浏览器反复进入和退出近景，没有形体突变、内院封闭、重复楼体或短暂消失。压缩容差单独说明，不用完整模型面数相等代替形体一致。

## 5. S2：逐栋校准普通建筑

### 5.1 数据契约

复用并完善 `data/building-overrides.json`、`scripts/building_overrides.py` 和现有来源目录。人工配置作为输入，`public/data/` 作为生成结果。

| 字段 | 用途与约束 |
| --- | --- |
| 稳定建筑 ID、轮廓版本 | 按 `way/…` 或 `relation/…` 定位，轮廓更新后检查锚点失效 |
| `category` | 保留导航及用途分类 |
| `archetype` | 表达宿舍、食堂、教学条形楼、实验院落、低矮配套等形制 |
| `levels`、`floorHeight`、`height` | 分开记录层数、层高和主体高度，冲突需说明 |
| `roof`、`parts` | 表达屋顶及主体/附楼/裙房分段，保留原始外环与内院 |
| `entrances` | 入口位置、朝外方位、宽度、主次及所依附立面 |
| `facadeRules` | 有依据的实墙、窗列、阳台设置，锚定具体立面 |
| `evidence`、`sourceRefs` | 逐字段注明来源、确认/估算/待核对状态及采用理由 |

坐标和方位约定应写入字段说明，明确数据/Blender 的 X 东、Y 北、Z 上与网页坐标的转换。人工覆盖失效、重复 ID、非法数值、未知来源或越界分段应报错；缺少资料进入待核对清单。

上表表达目标数据契约，不保证每个字段已在当前解析器中实现。落地时先映射现有字段和校验逻辑，只有现有结构无法表达可靠资料时才扩展，避免同时维护两套楼栋配置。

### 5.2 推进方式

候选楼栋按以下顺序选择：图书馆样板内影响入口视线与楼群比例的邻楼、巡游镜头中反复出现的普通楼、能够验证食堂/宿舍等不同形制的代表楼。每个候选同时记录可用资料；首批优先选择能定位入口方位、能识别主要体量且有层数依据的楼栋。

资料不足的候选保留在待取证清单，可由同区域、同形制且资料更完整的楼栋补入实施批次。图书馆样板必需的邻楼仍属于 S3 验收范围，不因替换 S2 候选而自动移出。候选数量、局部校准数量和整栋验收数量分别统计。

1. 先选 5–8 栋验证字段、资料工作量和生成效果。
2. 按字段应用有效人工覆盖、有效 OSM 信息及明确的默认规则，保留采用理由。
3. 食堂关闭宿舍式默认阳台；宿舍阳台也允许按立面关闭。
4. 有依据的入口覆盖自动入口；回退入口明确标为示意。
5. 每批记录“原参数 → 资料依据 → 新参数 → 未确认项 → 对照镜头”。
6. 试点通过后按区域扩展到 20–30 栋，检查楼群与地标之间的比例。

**完成计数：**建立一条记录不等于完成一栋。计入完成数量的楼栋应完成层数/高度、屋顶、入口和主要立面的核对流程，至少一项有依据的形体或入口校准已落地，并列明仍无法确认的字段。不得将保留默认值的建筑统计为实测。

### 5.3 单栋执行记录模板

每栋使用下表留存核对结果，便于后续批次接续；同一楼栋可以有多个字段来源，不能用一张正面照片为全部立面和尺寸背书。

| 记录项 | 必填内容 |
| --- | --- |
| 身份与范围 | 稳定 ID、楼名、轮廓摘要、所在区块、是否属于场地样板 |
| 修改前状态 | 层数及高度依据、屋顶规则、入口回退方式、固定镜头 |
| 逐字段依据 | 目标字段、来源链接、可确认内容、方位、资料日期、仍需估算的参数 |
| 采用方案 | 原值、新值、采用理由、受影响体量或立面；无依据字段保留待核对 |
| 输出与检查 | 输入与资产版本、源模型及 GLB 检查、前后截图、性能报告 |
| 当前状态 | 待取证 / 部分实现 / 待验收 / 已验收，以及剩余问题和下一步 |

批次汇总分别统计“建立记录的楼栋”“局部字段已校准的楼栋”和“整栋验收通过的楼栋”。20–30 栋目标以最后一项计数；局部成果可以先交付，但不能提前计入整栋完成数。

若入口朝向、主要体量或屋顶类型仍缺乏足以支持校准的资料，该楼栋保留“部分实现 / 待取证”状态。层高、入口宽度等尺寸可以采用有依据的估算并明确标注，但不能用“已登记未知项”替代关键形体的核对与验收。

## 6. S3：图书馆北入口完整场地样板

精修单位是“地标及周边的一片空间”。先用资料确认方位、入口与前场用途，再处理模型连接；选择图书馆是因为资料和独立模型较多。

主要入口：`blender/library.py`、`data/site-overrides.json`、`scripts/site_data.py`、`blender/site_geometry.py` 及完整数据准备流程。

- [ ] 核对南北体量、北门朝向、台阶和平台；区分已知尺寸与照片约束估算。
- [ ] 确定前场铺装范围，不将工作区域边界直接当作现实广场轮廓。
- [ ] 建立“实际道路铺面 → 前场/步道 → 台阶或平台 → 门口”的连续模型连接。
- [ ] 只在必要范围修整地形，处理铺面侧边、路缘和台阶底部，保留范围外地势。
- [ ] 使用最终道路几何校准接缝，避免重复铺面和共面闪烁；显示偏移与结构高度分开。
- [ ] 对平台、前场和入口通路执行树冠排除，保留有资料支持的开放空间。
- [ ] 校准影响样板比例的相邻普通建筑，纳入 S2 清单。
- [ ] 明确场地构件图层与基础模型归属，检查近景替换和图层开关后的完整性。
- [ ] 完成日间、夜景、关闭标签、基础/近景及手机尺寸的固定镜头对照。

**验收：**入口链没有可见的穿地、悬浮、缺口或非预期突变；台阶和挡墙有合理侧面与收口；内院、入口开口和绿化留白保留；关闭名称后仍能通过形体与空间组织对照参考资料。估算前场边界、宽度和坡度明确记录，不额外虚构坡道或设施。

## 7. S4：植被分区与局部场地推广

先复用树木模板，按实际空间用途组织树位。当前仓库已有 `data/vegetation-zones.json` 和 `scripts/vegetation_data.py`，实施时先核对既有规则及验证记录，再补充未覆盖的分区。

| 分区 | 规则 | 验收重点 |
| --- | --- | --- |
| 开放区域 | 前场、草坪、入口与必要视线范围设置禁植区 | 同时检查树干和树冠侵入 |
| 行道树 | 仅在有资料的道路设置侧线、间距和退让 | 保留路口、支路和建筑入口 |
| 庭院与湖边 | 依据边界或明确点位组织 | 保留步道、内院及主立面视线 |
| 背景绿地 | 保留受约束随机生成，采用局部稳定种子 | 局部修改不扰动其他区域树位 |
| 低矮景观 | 有依据时单独表达灌木、花坛和绿篱 | 类型正确，未取得资料者不补造 |

所有树位来源统一经过最终道路、水体、运动场和入口排除；禁植约束优先于行列及散点规则。已有汇学堂正东草坪树冠排除等规则必须持续有效。

场地推广先选一个有资料的代表性岸段和一处普通铺地边缘。分别处理“水面—岸坡/挡墙—岸顶步道”与“普通铺地—主路”的关系，验收后再扩大范围。

## 8. S5：细节与整体交付

形体和场地通过后，再处理固定镜头中仍有明确问题的材质、屋顶小构件、栏杆和装饰。每项细化记录可见收益与新增成本；优先使用材质或实例化表达重复细节。

- [ ] 确认首轮三项成果及 S4 推广区域均达到对应验收标准。
- [ ] 清理重复几何、过细远景构件及失效配置。
- [ ] 完成搜索、巡游、分享、图层与加载回归。
- [ ] 同步源文件、派生数据、全部受影响模型及清单哈希。
- [ ] 更新数据、建模和验证文档，保留历史记录及未确认资料清单。

## 9. 统一验收标准

### 数据与几何

检查覆盖优先级、有效数值、来源引用、稳定 ID、入口/立面锚点、外环和内院保留，以及可重复生成。模型同时检查可编辑源文件和实际解码 GLB。场地检查必须采样实际铺面与地形；树位检查覆盖树冠。

复用现有检查，并按受影响范围执行 `validate_generic.py`、`validate_site.py`、建筑专项与道路/桥下接口检查。各脚本的覆盖范围需明确，不能以一个道路检查通过代替全部场地验收。

### 画面与交互

使用 S0 的同组镜头、视口和画质做前后对照，记录加载稳定状态。检查三次近景进入/退出、图层切换、日夜、标签关闭及手机尺寸画面。控制台、资源加载和页面错误列入报告。

### 性能与资源预算

| 指标 | 计划约束 |
| --- | --- |
| 首屏基础模型与树模板 | `base.glb + trees.glb ≤ 6,000,000 bytes` |
| 单个普通近景区块 | `< 2,000,000 bytes` |
| 同条件活动帧率 | 三次结果的 FPS 中位数下降不超过 10% |
| 同条件渲染三角形与 Draw Calls | 增幅分别不超过 15% |
| 近景加载预算 | 沿用现有配置，不因增加细节直接扩大 |

帧率、三角形和 Draw Calls 的回归判断以 S0 实测为基线，近景加载预算沿用既有配置。精细和流畅档分别热身后执行相同 30 秒活动镜头，各重复三次，冷缓存首屏另测。记录设备、浏览器、生产版本、视口、像素比和并发负载；受其他重任务干扰的记录保留并注明，不能用于同条件通过结论。手机尺寸模拟与手机真机测试分别表述。

6 MB 首屏模型和 2 MB 近景区块门槛沿用仓库现有检查；帧率下降 10%、三角形与 Draw Calls 增幅 15% 为本轮计划采用的回归门槛，不是 6pro 原文提供的实测结论。资源预算仅统计模型与嵌入纹理，网页脚本、JSON 和解码器另行记录。

超出门槛时，先排查重复几何、材质批次、细节层级和加载问题，再决定取舍。6pro 提及的约 439 万/142 万三角形是历史特定视角记录，不作为本轮实测基线。

## 10. 风险、交付与完成定义

| 风险 | 处理方式 |
| --- | --- |
| 资料不足或方位误判 | 使用稳定 ID 和地图定位，交叉核对方位；未知字段保留估算或待核对 |
| 轮廓更新导致入口失效 | 保存轮廓版本，构建时检查锚点 |
| 多套场地处理互相覆盖 | 明确完整准备顺序，保留表面索引契约，最终统一排树 |
| 模型只更新一层 | 源文件、基础、近景与清单成套更新并校验 |
| 压缩误差误判为几何缺陷 | 区分源几何和量化容差，记录实测误差与容差依据 |
| 新增细节导致性能退化 | 每批按同条件基线检查，优先削减非必要细节 |

每批交付人工参数与来源、生成脚本、受影响派生数据与模型、检查报告、固定镜头对照和剩余问题清单。恢复旧版本时应恢复完整配套资产，避免新清单指向旧模型。

首轮完成以“三项成果全部通过”为准；全计划完成还需 S4 推广和 S5 总体验收通过。单项修复、若干试点记录或一个画面改善，均不代替整批完成。

### 单批验收记录模板

实施时将下表填入执行记录，并链接具体证据。状态采用“待取证 / 部分实现 / 待验收 / 已验收”；只有对应范围的必要检查全部通过，才记为已验收。

| 记录项 | 每批需要填写的内容 |
| --- | --- |
| 批次与范围 | 所属工作包、楼栋稳定 ID 或场地区域、计划解决的问题 |
| 修改前基线 | 输入版本、源文件及模型清单哈希、固定镜头记录 |
| 资料依据 | 来源链接、支持的具体字段、估算参数和未确认项 |
| 本批变更 | 人工配置、生成规则、受影响模型及范围外保留情况 |
| 验收证据 | 数据与实际导出几何检查、相同镜头前后对照、加载和图层检查 |
| 资源与性能 | 首屏及区块字节数、相同条件下的帧率/三角形/Draw Calls、测量限制 |
| 完成计数 | 本批整栋验收数、累计整栋验收数；局部修复单独列出 |
| 后续动作 | 未通过项、资料缺口、下一批任务与进入条件 |

若只完成入口或某一立面，记录该局部成果，并继续保留整栋待验收状态。性能数值达标但测量条件不可比时，记录数值和限制，保留性能待验收项。

## 11. 可直接领取的实施工作包

以下清单用于按顺序推进；已在执行记录中有完整证据的工作包先复核，复核通过后接续下一项。

| 工作包 | 输入 | 具体产出 | 完成条件 |
| --- | --- | --- | --- |
| W0 基线复核 | 当前代码、数据、模型和已有报告 | 一份版本一致的基线索引；20–30 栋候选及样板范围 | 报告能对应实际资产，资料缺口逐栋登记 |
| W1 形体一致性 | 普通建筑生成器与屋顶样本 | 共享形体规则、基础/近景导出、切换对照 | S1 的几何与浏览器验收通过 |
| W2 校准试点 | 5–8 栋稳定 ID、轮廓和可定位资料 | 逐字段校准表、必要的解析器扩展、成套模型 | 原型、层数、屋顶、入口均有核对结论；推定项明确标注 |
| W3 场地样板 | 图书馆北入口资料、最终道路几何及邻楼清单 | 连续入口空间、绿化留白、邻楼校准与固定镜头报告 | S3 全部条件通过，不能只验收门前平台 |
| W4 楼栋扩展 | 已验证的试点方法和剩余候选 | 累计 20–30 栋完整核对记录 | 按第 5 节计数，批次性能与楼群比例检查通过 |
| W5 空间规则推广 | 有依据的植被分区、代表性岸段和普通铺地 | 行道树/庭院/背景/低矮景观规则及两类场地示例 | 来源、接缝、树冠排除、范围外不受扰动均可验证 |
| W6 收尾交付 | 前述全部通过的工作包 | 必要细化、完整模型清单、总体验收与未确认项列表 | S5 与统一验收标准通过 |

每个工作包使用同一记录格式：**范围与稳定 ID → 资料与不确定性 → 修改前问题 → 参数和几何变更 → 自动检查 → 固定镜头对照 → 性能结果 → 尚未完成项**。资料不足时先推进其他有证据的楼栋或区域，原任务保留“待取证”状态。

实施入口和复现命令见[实施计划](CAMPUS_REFINEMENT_PLAN.md)及[建模说明](MODELING.md)；实际完成状态和历史证据统一维护在[执行记录](CAMPUS_REFINEMENT_PROGRESS.md)。本文件作为 6pro 建议的总体规划与验收依据。

## 12. 首批执行步骤

启动时按下列顺序领取任务。当前仓库已有实现的项目先复核证据，复核通过即可跳到下一项；不重复生成已经验收的成果。

1. **核对基线与缺口。** 将现有执行记录对应到当前输入、脚本和模型版本；整理已验收项、部分完成项、待取证项和待验收项。基线不一致时，先为本批保存可复现快照。
2. **确认普通建筑形体一致。** 选取旋转矩形、内院及低矮建筑样本，核对实际基础/近景模型和浏览器切换。若仍有屋顶或主体突变，先在共享形体层修复，再进入楼栋校准。
3. **确定第一批 5–8 栋。** 优先从图书馆样板邻楼中选择，同时覆盖食堂与宿舍；按稳定 ID 建立资料清单。为每栋列出高度、屋顶、入口、附楼及主要立面的已知项与缺口。
4. **完成一栋端到端试点。** 从可定位资料出发，更新人工参数，生成源文件与受影响资产，验证几何、画面和预算，形成可复用记录。试点通过后再按同一流程处理本批其余建筑。
5. **联合验收样板空间。** 在相同镜头中检查图书馆入口、场地、相邻道路、绿化和本批邻楼；未通过的连接或比例问题回到对应数据和几何层修正。
6. **决定后续批次。** 根据试点的资料获取难度、构建成本和实际验收结果，安排剩余楼栋及 S4 场地推广顺序。每批结束更新完成数量和待核对字段，直至首轮三项成果全部达标。

单批集成顺序为：**保存基线 → 整理资料 → 修改人工输入与必要脚本 → 生成派生数据及模型 → 校验清单和哈希 → 几何与画面检查 → 同条件性能检查 → 更新执行记录**。发生回退时恢复该批配套输入与资产，并保留失败报告，避免只恢复某个 GLB 而留下不匹配的数据或清单。
